# EspNowBus — サンプル入門ガイド

> English: [GUIDE_EXAMPLES.md](GUIDE_EXAMPLES.md)

グループ化したESP-NOW通信と配送状態を確認するためのガイドです。

[ライブラリREADME](../README.ja.md)で導入と対応環境を確認し、[サンプル一覧](../examples/README.ja.md)から例を選びます。Versionやボードの対応表、既定の内部容量はここへ複製せず、元の説明を参照します。

## 準備から確認まで

1. 目的が近い最小例を選び、必要なボード、機器、依存ライブラリ、同梱ファイルを確認します。
2. GPIO・相手・入力ファイルなどを実際の環境に合わせます。未接続の仮実装は各例のREADMEにあります。
3. .inoを開いてボードとポートを選び、書き込みます。シリアルを使う場合は速度を合わせます。
4. 初期化、入力、処理、出力のどこまで進んだか順に確認します。コンパイル成功だけでは実機の入出力は確認できません。
5. まず例の入力と設定で動かし、変更は1つずつ行います。

## APIとデータの扱い

互換な相手とグループ設定・Wi-Fi チャンネルを合わせます。基本例のgroupNameには__FILE__が入るため、違うスケッチ同士では共通の名前を明示しないと別グループになる場合があります。まず対応する組を再現し、アドレス・チャンネル・Securityを意図して変更します。

キュー受理、物理的なSentOk、アプリのAppAckReceivedは別の段階で、App ACKでも下流装置の動作完了までは示しません。BroadcastにUnicastと同じ相手ごとのACKはありません。受信データには長さがあり、例の文字列は終端付きでも任意のバイナリがそうとは限りません。

必要な値はコールバックから戻る前にコピーし、loopと共有する状態は同期します。シリアル／IP用アダプタには独自の区切り・バッファ・機器／ネットワーク設定があり、無線PacketだけでInternetへつながるわけではありません。

## 組み込むときに確認すること

- 戻り値がbool、処理量、ハンドルのどれかを確認し、失敗時に古い値を利用しないようにします。
- 登録したコールバックは、その行で実行されるのではなく、後で該当する処理場所から呼ばれます。共有値の同期と参照先の寿命を決めます。
- 配列を渡すAPIではByte・サンプル・フレーム・ピクセルなどの単位を混同せず、容量と有効長を分けます。
- ビュー、ポインタ、バッファを保持する期間を確認します。ポインタをコピーしても参照先は複製されません。
- 最小例が省略した失敗時の処理、再試行、終了時の解放は、用途に合わせて追加します。

## 各例のREADMEで読む場所

「準備と実行」で機器と手順、「動作の流れ」で実際に使うAPI、「注意点」で用途固有の制約を確認できます。出力が見えない場合は、初期化に成功したか、処理を進める呼び出しが継続しているか、入力や相手が準備できているかを順に見ます。
